# gpt-image-2 可视化提示词：法规识别并输出控制点流程

```text
创建一张专业、清晰、信息密度适中的流程可视化图片，主题是“法律法规识别并生成合规控制点的自动化流程”。

画面风格：
- 企业级合规科技 / 信息安全审计风格
- 干净的白底或浅灰背景
- 使用蓝色、青色、深灰作为主色，少量绿色表示通过，橙色表示需复核，红色表示失败
- 扁平化信息图，不要卡通人物，不要复杂装饰
- 适合放在项目说明文档或演示文稿中
- 横向布局，16:9 比例

画面结构：
从左到右展示完整流程，使用箭头连接各阶段。

阶段 1：输入
标题：法律法规 PDF 输入
元素：
- PDF 文件图标
- 示例文件名：中国网络安全法、数据安全法、个人信息保护法
- 旁边标注：原始法律文本 / 法规条款

阶段 2：PDF 解析
标题：PDFParser 文本解析
元素：
- OCR / 文本提取图标
- 页面被拆分成章节和条文
- 标注：
  - 清理目录、页码和噪声
  - 识别章节、节、条文
  - 生成 chapter -> articles 结构

阶段 3：章节分析
标题：Analyst 阶段：章节摘要
元素：
- 文档摘要图标
- 输入：章节标题、组织画像、条文导览
- 输出：核心主题、高频实体、审计关注方向
- 标注：用于压缩上下文，帮助后续控制点识别

阶段 4：条文适用性判断
标题：适用性过滤
元素：
- 漏斗图标
- 判断条件以小标签展示：
  - 是否适用于企业 / 网络运营者
  - 是否是监管机关职责
  - 是否涉及 ABB 适用场景
  - 是否为 CII 客户供应商承接责任
- 输出分支：
  - 不适用 -> 跳过
  - 适用 -> 进入控制点生成

阶段 5：Auditor 阶段：控制点生成
标题：Auditor 阶段：生成候选控制点
元素：
- AI 审计师 / 规则引擎图标
- 输入：当前条文 + 章节上下文 + 控制域标准
- 输出：Markdown 表格行
- 展示一个小型表格，列名为：
  涉及领域 | 控制目标 | 法律要求 | 控制点 | 类型
- 标注：
  - 法律要求必须引用当前条文号
  - 控制点必须包含动作、检查对象、审计证据
  - 控制域必须来自标准列表

阶段 6：Reviewer 阶段：质量评审
标题：Reviewer 阶段：质量校验
元素：
- 检查清单图标
- 三个判定结果：
  - PASS：进入最终矩阵
  - REVIEW：进入复核清单
  - FAIL：丢弃或记录异常
- 标注：
  - 校验格式
  - 校验法律追溯
  - 校验可审计性
  - 校验适用性

阶段 7：本地规则校验
标题：程序规则校验
元素：
- 代码校验 / 盾牌图标
- 标注：
  - 5 列 Markdown 表格
  - 控制域合法
  - 类型为“强制”
  - 只引用一个当前条文
  - 自动规范化法律要求摘录

阶段 8：输出
标题：最终输出文件
元素：
- 两个文件图标
- 文件 1：合规矩阵 Markdown
  内容：通过评审的控制点
- 文件 2：复核清单 Markdown
  内容：需人工复核、格式异常、模型异常输出
- 右侧强调最终成果：
  “可审计、可追溯、可复核的合规控制点”

额外视觉要求：
- 在流程底部放一条细线表示“治理原则”：宁缺毋滥、条文可追溯、证据可核查、控制域标准化
- 不要生成真实公司 logo
- 不要使用过多小字，文字要清晰可读
- 整体像一张严谨的系统流程架构图，而不是营销海报
```
